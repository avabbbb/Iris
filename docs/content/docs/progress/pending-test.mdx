## 本轮：AE 场景替换原生效果源码与候选应用入口

- 已实现源码：AE C++ 效果改为读取宿主 `Asset Version` 图层参数并按当前帧混合输入，移除了将 `PF_Param_PATH` 当普通文件路径的错误路径；未实现 `extent_hint` 和输出偏移处理前不声明输出范围支持。面板生成后先导入候选，用户再显式应用到提交时绑定的原始合成/图层。目标不存在时明确失败，不切换到当前活动目标。
- 已实现源码：候选导入和效果应用各自归入 AE Undo Group；新效果创建后参数配置失败会移除半成品效果。Studio 构建清单与效果参数清单同步为 `Asset Version` / `Blend`。
- 已实现源码：候选图层默认关闭可见开关，只有用户执行“应用”后才影响原合成；CEP 清单要求 AE 22.0+，宿主也会在缺少稳定合成/图层 ID 时返回版本提示。候选关闭时仍能否被效果采样待真实宿主确认。
- 已实现源码：AE 候选恢复检查当前合成的 FootageItem 文件状态和字节数；候选页可手动刷新，文件缺失或长度不符时显示原因、禁用列表应用与当前结果的顶部应用按钮。CEP 应用桥接在调用 ExtendScript 前按候选 ID 重新读取当前合成清单，并校验候选绑定的合成、源图层、文件字节数与 SHA-256；校验失败不会进入宿主应用调用。缺失素材仍没有重新定位/回链入口。
- 已实现源码：候选导入先写入同目录唯一暂存文件，回读校验字节数和 SHA-256 后再通过 CEP rename 提交到内容寻址路径；校验不匹配时不导入，固定版本路径已存在时只在现有文件哈希匹配后复用，不覆盖它。Apply 前会再次读取文件，所以同尺寸替换会被拒绝。真实 CEP rename、Web Crypto 兼容与并发渲染未在 AE 验证。
- 已实现源码：AE 8-bit 效果对不同尺寸的输入/候选素材使用像素中心双线性重采样后混合 RGBA；尺寸相同时走逐行直接采样，避免不必要的插值。尚未编译或与参考渲染/性能基线对比，alpha、颜色空间和宿主实际采样行为仍待真实 AE 验证。
- 已实现源码：AE 参考素材物化带上提交时冻结的合成 ID、图层 ID 与图层时间；脚本把所选图层复制到单帧临时合成，使用独立 Render Queue 项和 PNG Alpha 模板，只暂时取消既有 QUEUED 项并在收尾恢复，失败时清理临时项目和输出。未在真实 AE 验证帧选择、输出模板、队列恢复、取消路径，以及父级/轨道遮罩/相机/跨图层效果依赖是否完整保留。
- 已实现源码：AE 候选导入时把宿主报告的画幅、时长、帧率/帧时长、像素宽高比、Alpha 解释，以及 AE 项目工作色彩空间、Gamma、位深和线性化设置写入候选图层注释；候选恢复接口会返回这些字段，面板候选项也展示主要信息。它们描述 AE 导入解释与项目上下文，不代表嵌入素材色彩配置或权威帧数；当前实现未在真实 AE 验证这些属性读取或候选数据回读。

## 已记录回归：workflow.project.use 浏览器激活缺失

- 症状：外部 Agent 运行 `workflow.project.use --project-id X` 后返回 `ok` 与 `{ projectId: X }`，但 `/health`（`workspace.status`）的 `activeProjectId` 仍是旧项目；后续 `workflow.inspect --agent-identity codex` 读取的仍是旧项目，若再对 X 显式传 `--project-id X` 会被 `agent/session.js:355` 以 `LEASE_TARGET_CHANGED` 拒绝——`project.use` 表面上成功，实际没有切换 agent 侧绑定目标。
- 根因：命令只穿过 Browser 执行，且没有任何「切换确认」握手。链路为 `cli.js → IrisWorkspaceClient.execute → POST /api/tools → agent/session.js callCommand:331 → SSE tool_call → services/workflowAgentBridge.ts:270 → workflowDispatcher.ts:242-246`。`workflowDispatcher.ts:244` 的 `dependencies.setActiveProject(projectId)` 只改浏览器 store 的 `activeProjectId`（`components/workflow/store.ts:191`），随后 dispatcher 立即返回 `{ projectId }`——它只是回显请求参数，不是浏览器已切换的 ack。agent 侧绑定要等浏览器 store 订阅触发 `workflowWorkspaceAdapter.update()` → `pushSnapshot` → `POST /workflow/state` → `agent/session.js:96-117 updateSnapshot` 后才更新；由于 `project.use` 不在 `LEASED_WORKFLOW_COMMANDS`（`agent/session.js:7-12`）内，session 对该命令不取 lease、不等快照，resolve 时机早于回环完成。在这段窗口内 `callCommand:347` 的 `boundSnapshot` 仍是旧 projectId：`/health` 的 `activeProjectId` 读旧值，对 X 显式传 `--project-id` 的后续写入会被 `callCommand:355-365` 以 `LEASE_TARGET_CHANGED` 拒绝，而不带 projectId 的 `inspect` 读到旧项目。本地指针更新（`setActiveProject`）被当成交互终点，browser→agent 的状态回环完全在临界区之外。
- 预期语义（浏览器激活命令）：`project.use` 应是一条浏览器激活 RPC，而非普通 mutation——`callCommand` 收到后向 Browser 发送「切到项目 X」请求；浏览器 `setActiveProject(X)` → store 变化触发 `pushSnapshot(X)` → session `updateSnapshot` 把 `boundSnapshot.id` 更新为 X → 此时才向调用方 resolve，并让下一次 `ensureWorkspaceLease` 在 X 上签新 lease。当前实现把「本地指针更新」当成交互终点，绕过了 browser→agent 的状态回环，于是 inspect/lease/写目标三者各自依据不同时间点的快照。
- 为何暂不修：不在 5/5 Golden Task 的关键路径上——trial 走 `workflow.project.create`（新项目自动成为 active 并经 pushSnapshot 自然绑定），`project.use` 只在「跨已有项目切换」场景才暴露；修复需要在 session ↔ browser 之间新增一轮「切换确认」握手的真实行为改动，按用户指示作为独立回归跟踪，不混入本轮外部门禁收尾。预期语义已冻结为 [ADR 0072](../../../archive/2026-10-07/adr/0072-project-use-is-a-browser-activation.md)。
- 修复草案：把 `workflow.project.use` 加入 leased/确认命令集，或在 `callCommand` 里对它特判为「发送 tool_call → 等 boundSnapshot.id === args.projectId（带超时）→ resolve」；同时让 `workflowDispatcher.project.use` 分支在浏览器侧返回新 `activeProjectId` 作为 ack 载荷，而不是仅回显请求参数。
