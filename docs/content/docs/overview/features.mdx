Iris 当前是 local-first、agent-native 的视觉制作工作台。人和 Coding Agent 操作同一份可见 Workflow；模型、API Key、素材与最终编辑权仍在用户一侧。

## 当前产品 surface

| Surface | 当前职责 | 当前边界 |
| --- | --- | --- |
| **画布 Canvas** | GenAI 生成与 Workflow 基本盘：节点、素材、连线、生成与版本 | 当前主要创作面 |
| **Cut**（内部视图 id 仍为 `reverse`） | 浏览器内视频剪辑器：多轨时间线、字幕、属性、预览代理、波形、MP4 导出（WebCodecs，写入 OPFS）、成片回画布；子页「故事版 · 逆向」把参考视频拆成镜头表并可转为画布子画布；内置 Agent 通过 `iris_cut_*` 工具操作同一个工程 | `cutStore` 是 Cut 工程的唯一权威；需要支持 WebCodecs 的浏览器；Resolve 等宿主上下文连接器仍是设计目标 |
| **Agent** | Agent 连接与状态：Codex、WorkBuddy 等本地/外部 Coding Agent 的发现、准备、状态与切换 | **不是聊天页**，不嵌内置 Assistant |

Canvas 旁边有右侧 contextual drawer：**Assistant / Context / History**。Assistant 是 Iris 内置助手；它不拥有比外部 Agent 更高的工具权限，也不承担 Host 连接管理。

这套 IA 以当前顶栏和运行代码为准。旧的“Agent full-page chat workspace”与“Agent 只剩 global drawer”都已归档。

## Agent 操作

外部 Agent 默认通过 Agent Integration Skill + CLI 使用 Iris。稳定日常操作为：

- `status`
- `workflow.inspect`
- `workflow.selection.get`
- `workflow.apply`
- `workflow.node.run`

`ensure` / `doctor` 用于连接准备和诊断。stdio MCP 是同一 operation contract 的可选投影，不维护第二份业务实现。

Codex、Claude Code、OpenCode、WorkBuddy、TeleAgent 的真实支持级别分别见 [Support Matrix](../../../../SUPPORT_MATRIX.md)，不能用一个 Host 的成功推导其它 Host 已可用。

## Workflow 与媒体

Canvas 支持图片、视频、音频、文本与配置等 Workflow 节点，以及引用、连线、局部媒体工具和可见结果。

Iris 的逆向拆解工具只通过一次明确的 `workflow.apply`（子画布节点）写入 Canvas，不与 Canvas 隐式双写状态。

## Provider 与本地数据

- 当前 Web/Browser Workflow 仍是稳定 Agent operation 的可见权威。
- 用户自行配置 Provider；真实费用、限流、取消与提交未知需要按 Provider 分别验证。
- Browser 与 Desktop Runtime 的凭据/任务边界仍需如实区分。
- 连接器、Skill、项目与日志不应携带 Provider 原始 key。

## 创作软件宿主

Photoshop / Premiere / After Effects / Resolve 目前按 [Support Matrix](../../../../SUPPORT_MATRIX.md) 标记真实证据等级。原生效果、保存重开、关键帧与离线导出只有通过真实宿主验证后才升级为正式能力。

完整产品边界见 [当前主设计](../../../design/00-overview.md)。未完成工作见 [后续待办](../progress/todo.mdx)，已实现但仍需现实环境确认的内容见 [待测试确认](../progress/pending-test.mdx)。
