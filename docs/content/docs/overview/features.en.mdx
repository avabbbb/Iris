Iris is currently a local-first, agent-native visual production workspace. Humans and coding agents operate on the same visible Workflow while providers, API keys, assets and final editing remain under the user's control.

## Current product surfaces

| Surface | Responsibility | Boundary |
| --- | --- | --- |
| **Canvas** | GenAI generation and the base Workflow: nodes, assets, connections, generation, versions | Primary creation surface |
| **Cut** (internal view id still `reverse`) | In-browser video editor: multi-track timeline, subtitles, inspector, preview proxies, waveforms, MP4 export (WebCodecs, written to OPFS), export back to the canvas; the "Storyboard · Reverse" sub-view breaks a reference video into a shot table and can turn it into a canvas sub-graph; the built-in Agent edits the same project through `iris_cut_*` tools | `cutStore` is the only authority for the Cut project; needs a browser with WebCodecs; Resolve and other host context connectors are still design targets |
| **Agent** | Agent connections and state: discover, prepare, inspect and switch local/external coding agents such as Codex and WorkBuddy | **Not a chat page**; does not embed the built-in Assistant |

Canvas has a contextual right drawer: **Assistant / Context / History**. The built-in Assistant has no extra privilege over external agents and does not manage host installation or connection.

Older designs that made Agent a full-page chat workspace, or removed the top-level Agent surface entirely in favor of one global drawer, are historical only.

## Agent operations

External agents use the Agent Integration Skill + CLI by default. The stable daily surface is:

- `status`
- `workflow.inspect`
- `workflow.selection.get`
- `workflow.apply`
- `workflow.node.run`

`ensure` and `doctor` handle connection setup/diagnostics. The stdio MCP server is an optional projection of the same operation contract, not a second implementation.

Real support levels for Codex, Claude Code, OpenCode, WorkBuddy and TeleAgent are tracked independently in the [Support Matrix](../../../../SUPPORT_MATRIX.md).

## Workflow and media

Canvas supports image, video, audio, text and configuration nodes plus references, connections, local media tools and visible results.

Iris's reverse-breakdown tool writes to Canvas only through an explicit `workflow.apply` (a subgraph node); it does not silently mirror Canvas state.

## Providers and local data

- The visible Browser Workflow remains the current authority for stable agent operations.
- Users configure their own providers; billing, rate limits, cancellation and unknown-submit recovery are verified per provider.
- Browser and Desktop Runtime credential/task boundaries are documented separately.
- Connectors, Skills, projects and logs must not carry raw provider keys.

## Creative hosts

Photoshop, Premiere, After Effects and Resolve are reported only at the evidence level in the [Support Matrix](../../../../SUPPORT_MATRIX.md). Native effects, save/reopen, keyframes and offline export become supported only after real-host verification.
